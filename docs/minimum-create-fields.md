# Предложение минимальных полей для создания

Это предложение, а не действующая политика записи. Разделы 4, 14 и 15 доменного
контракта отмечают бизнес-обязательность полей как `[U]`; до утверждения владельцем
MCP не создаёт и не изменяет записи.

| Сущность | Минимум для первоначальной записи | Обоснование |
|---|---|---|
| Клиент | `Клиент`, `Тип клиента`, `Проверка конфликта` | Нужен различимый субъект, а тип и явно зафиксированное состояние conflict check предотвращают неявное допущение о проверке. `Статус клиента` не включён: начальный lifecycle-статус не определён. |
| Дело | `Дело`, `Клиент` | Нужны предмет поручения и его носитель. Не создаёт правила о стадии, номере, суде, датах или гонораре. |
| Задача | `Задача` | Схема допускает отсутствие обеих связей; требование клиента/дела и их согласованности имеет статус `[U]`. |
| Взаимодействие | `Взаимодействие`, `Дата` | Без даты журнал события не выполняет свою базовую функцию. Привязка к клиенту/делу — наблюдаемая, но не утверждённая конвенция. |
| Документ | `Документ` | Метаданные без файла допустимы по контракту; обязательность файла и связей имеет статус `[U]`. |

После утверждения требуется отдельная реализация write-поверхности: runtime metadata
перед каждой записью, allowlist, проверка ID/типов/choices/cardinality, idempotency,
версионная precondition, журнал, а для delete — plan/confirm/apply.
