# Dossier MCP

Минимальный MCP-сервер для демонстрационной базы Teable «Досье». Сейчас он намеренно
read-only: поиск клиентов и чтение карточки по `rec...`. Создание, изменение, удаление,
вложения и изменения схемы не реализованы, поскольку обязательные бизнес-поля и правила
переходов в доменном контракте имеют статус `[U]`.

## Установка

Нужен Python 3.14 и `uv`.

```sh
uv sync --group dev
```

Создайте локальный `.env` (он игнорируется Git):

```dotenv
DOSSIER_MODE=development
TEABLE_TOKEN=...
# Не включайте без отдельного разрешения:
# DOSSIER_ALLOW_PII_READ=1
# Для self-hosted Teable можно задать TEABLE_ENDPOINT=https://...
```

Переменные окружения должны быть переданы процессу сервера; `.env` не считывается
автоматически, чтобы не сделать секретный файл неявным каналом конфигурации.

## Запуск и подключение

```sh
set -a; . ./.env; set +a
uv run dossier-mcp
```

Подключите к Codex локальный stdio-процесс `uv run dossier-mcp`. HTTP/SSE transport не
включён. В обычной конфигурации доступны `dossier_status`,
`minimum_create_field_proposal`, `find_clients` и `get_client_dossier`.

## Проверки

```sh
uv run ruff check .
uv run pyright
uv run pytest
```

## Режимы и изоляция

`DOSSIER_MODE` обязателен и принимает только `development` или `demo`. В обоих режимах
сервер не включает write-доступ. Для demo нужно запускать отдельный процесс от отдельного
OS-пользователя, с отдельным Teable token, отдельным каталогом runtime и MCP-конфигурацией,
недоступными developer-пользователю. Не передавайте demo-token, логи или runtime-файлы в
этот репозиторий. Режим определяется окружением процесса, а не аргументом инструмента.

Минимальные поля, предлагаемые для будущего согласования, описаны в
[`docs/minimum-create-fields.md`](docs/minimum-create-fields.md).
